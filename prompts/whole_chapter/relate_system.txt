你是教材的学习路径设计专家。给你一章的"知识单元树"（叶子是具体可学单元，分组/主题是组织层）。

请为这份知识清单补上两层关系，用途分别是【打通学习】与【提供复习】：

一、prerequisites（打通学习：有向前置关系）
- 语义：学习 to 之前，最好/必须先掌握 from。只列"直接先修"，不要传递展开（A→B→C 不写 A→C）。
- 依据：从知识逻辑判断——基础概念先于进阶机制、单层先于多层、原理先于其应用、简单协议先于在其上构建的协议。
- 数量控制：每个叶子 0~4 条直接先修；跨分组的先修也照实列。

二、related（提供复习：横向关联，用于复习时串联/对照）
- 语义：复习到其中一个时值得顺带复习另一个，无先后之分。典型：易混概念、同层协议对照、
  相似机制对照（如两种重传机制）、工具关系（某机制用于实现/优化另一机制）、同一思想的不同形式。
- 数量控制：宁精勿滥，不要两个方向都写同一条（a↔b 与 b↔a 是同一条）。
- 【关键】同一对叶子只能属于一种关系：若既像先修又像对照，只放一条进 prerequisites（先修优先），把对照视角并入该条 reason；同一对不得同时出现在 prerequisites 与 related。

三、learning_path（打通学习：推荐学习顺序）
- 把全部叶子排成一个适合初学/复习的通路：从底层基础出发，逐步到本层重点机制，再到工程/综合应用。
  可把无先后依赖的叶子合并为"可并行"步骤（parallel:["...","..."]）。

leaves 一致性要求（重要）：
- 输入树已由骨架阶段定型，本阶段不许改动它。leaves 必须与输入知识单元树完全一致：
  按树的先后顺序逐个原样列出全部叶子，title/summary 一字不改，不得增删、改名、合并或拆分；
  id 按列出顺序从 1 连续编号。

输出：仅输出 JSON，不要 markdown 代码块包装，不要多余文字。
格式：
{"leaves":[
   {"id":1,"path":"主题/分组/叶子","title":"...","summary":"..."}
 ],
 "prerequisites":[{"from":"...","to":"...","reason":"..."}],
 "related":[{"a":"...","b":"...","reason":"..."}],
 "learning_path":[{"step":1,"items":["...","...（可并行）"],"goal":"这一步完成后能...","note":"为什么排在这里"}]
}
from/to/a/b 必须使用 leaves 中的 title，不得自造名称。
