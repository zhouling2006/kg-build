# 静态计算图与动态计算图

计算图按构建方式分为静态计算图与动态计算图。两者在构建时机、优化方式和灵活性上各有侧重，而现代深度学习框架已融合两者优势，使自动微分成为系统的基础能力。

## 静态计算图

<!-- @anchor-begin id="static-computational-graph" terms="1" note="静态计算图的定义与特点" -->
**静态计算图**（Static Computational Graph）通常在程序执行前，先构建并优化整张计算图。
- **优势**：由于在执行前已经获得了完整的计算拓扑结构，系统可以对其进行全局优化（如算子融合、内存复用）和高效的并行调度。
- **局限**：对于包含动态控制流（如依赖于运行时数据的条件分支或循环）的程序，静态图的构建和调试较为困难。
<!-- @anchor-end -->

## 动态计算图

<!-- @anchor-begin id="dynamic-computational-graph" terms="2" note="动态计算图的定义与特点" -->
**动态计算图**（Dynamic Computational Graph）则在程序运行时，按照实际的代码控制流即时构建计算图。
- **优势**：灵活性极高，能够原生支持复杂的动态控制流，且由于计算图的构建与代码执行同步，开发者可以像调试普通程序一样进行单步调试。
- **局限**：由于图结构在运行时才逐步展开，难以在编译阶段进行全局的图级优化。
<!-- @anchor-end -->

## 现代框架的融合与工程实践

现代深度学习框架已经不再简单地将计算图割裂为“静态图”或“动态图”两类，而是往往同时支持动态求导和图执行优化。从常见框架的设计来看：

- **PyTorch**：通常在前向计算时动态记录运算图，并通过 `backward()` 进行反向自动微分。
- **TensorFlow 2**：主要通过 `tf.GradientTape` 在 eager 模式下记录计算，也可以配合 `tf.function` 将动态记录的计算转换为图执行，以获取性能优化。
- **JAX**：将 `grad`、`jvp`、`vjp` 等自动微分操作视为程序变换，可以与 `jit` 等编译机制组合使用，实现高效的图执行优化。

从工程实践上看，自动微分已经成为深度学习系统的基础能力，而不再只是某一种特定框架的附加功能。
